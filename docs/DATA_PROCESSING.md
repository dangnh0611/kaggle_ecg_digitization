Details of important files/directories:
- `REFERENCE_TEMPLATE_FS100.png`: the **blank template** generated using [ecg-image-kit](https://github.com/alphanumericslab/ecg-image-kit) as an empty image without any lead waveforms, acting as a blank template with just grids, calibration pulses, separation ticks, and lead names
- `cv/`: Cross validation metadata, containing image ids for each fold split, generated by [../notebooks/cv_split.ipynb](../notebooks/cv_split.ipynb)
- `imc_results.json`: initial results obtained from MINIMA-RoMa dense matcher, produced by [../notebooks/find_matching_homo.ipynb](../notebooks/find_matching_homo.ipynb). We used wrapped API of [image-matching-webui](https://github.com/Vincentqyw/image-matching-webui) (also embeded as [a third party in this repo](../third_party/image-matching-webui)) to produce Homography transformation matrix from each image to the reference image (type 0001, shape 1700x2200). The image rotation information of either 0/90/180/270 degree also automatically determined in this matching process, simply by looping through all the 4 posible of rotations above, then obtain one with maximum number of matched keypoints.
- `keypoints_by_{homo,model}.{csv,npy}`: produced by [../notebooks/roma_match_keypoints.ipynb](../notebooks/roma_match_keypoints.ipynb), contains the 2422 keypoints's coordinates for all 8793 images in the official training dataset.
  - `keypoints_by_homo` variant are produced by applying perspective transform using estimated global Homography transformation matrix of `imc_results.json`, which is not accurate when local distortion appear, or the ECG sheet is not lying in a planar. We did not extensively used this keypoint coordinates in subsequence experiments.
  - `keypoints_by_model` variant are produced by directly apply interpolation on the dense matcher's estimated flow map (e.g, `warp_A` and `warp_B` of RoMa's output). This produces much better keypoints quality with subpixel accuracy so were used in keypoints detection training pipeline on the first round.
- `keypoints_by_round1.{csv,npy}`: keypoints coordinates generated as results of the first pseudo labeling round. We first use the initial pseudo label from `keypoints_by_model` to train 5-folds UNet model (round 1), then collect the OOF predictions, apply some postprocessing to produce this 2 files. More detailed steps are listed in the subsequence section [Iterative Pseudo Labeling Round 1](#iterative-pseudo-labeling-round-1)
- `keypoints_by_round2.{csv,npy}`: keypoints coordinates generated as results of the 2nd round Keypoints Detection model's training. In this round of training, pseudo label `keypoints_by_round1` was used as groundtruth to train the 2nd set of 5-folds models, also used in the [final submission notebook](https://www.kaggle.com/code/dangnh0611/5th-place-solution). Details about training these models are already listed in the [Solution Reproducing](../README.md#keypoints-detection-models-training) instructions and the subsequence section [Iterative Pseudo Labeling Round 2](#iterative-pseudo-labeling-round-2). After obtain the models's OOF predictions, we applied postprocessing pipeline defined in [../notebooks/pseudo_label_v2_round2.ipynb](../notebooks/pseudo_label_v2_round2.ipynb)
- `pseudo_label/`: OOF predictions of round 1 and round 2 training of Keypoints Detections. Example instructions to produce those files are noted in the subsequence section [Iterative Pseudo Labeling Round 1](#iterative-pseudo-labeling-round-1), and similar process was applied for round 2 in [Iterative Pseudo Labeling Round 2](#iterative-pseudo-labeling-round-2).
- `pseudo_test/`: csv files share the same format as official competition data's `test.csv` for local development/testing the submission code only.
- `reference_keypoints.json`: contains standard coordinates of 2422 keypoints (57 main keypoints + 2365 grid keypoints) by inspecting the [ecg-image-kit](https://github.com/alphanumericslab/ecg-image-kit)'s source code and script's output. Some dirty hint/details contained in [../notebooks/standard_keypoints.ipynb](../notebooks/standard_keypoints.ipynb), though we won't recommend :D
- `templates/`: contains per-lead cropped blank templates for different crop size. `fs100` means this is generated using a 100Hz example ECG record. As you already known, even when we did not render the lead waveforms, the blank templates are not strictly identical across different sampling rate, especially about the calibration pulse (which compute x-coordinate based on `step_size`, which is derived from `sampling_rate`). But we think it's just not important, we can use 100Hz blank template without any problems.


## Iterative Pseudo Labeling Round 1
MINIMA-RoMa's initial pseudo keypoints label was used as ground truth to train this round 1 model. The training pipeline is roughly similar to the round 2 stage used in final submission, with detailed reproduce instructions listed in [Solution Reproducing](../README.md#keypoints-detection-models-training), just differ in some training hyperparameters and ground truth keypoints label. Now we'll go step by step in case you want to fully reproduce the results yourself.


### (1) Training 5-folds Stage 1 Heatmap models

**Training command:**
```bash
python3 -m yagm.run -m local=local 'cv.fold_idx=null' exp_name=CONVNEXT_2048_GLS_ALLFOLDS exp=keypoint_detection_exp optim.lr=1e-4 scheduler.min_lr_factor=1e-3 loader.train_batch_size=1 trainer.accumulate_grad_batches=8 'loggers=[csv,wandb]' loader.train_num_workers=16 loader.val_num_workers=16 callbacks.model_checkpoint.save_top_k=1 trainer.compile.mode=model 'loss.mtl.loss_weights=[1,0,0,1]' loss.mtl.weight_method=gls loss.main.heatmap_loss=jsd data.main_sigma=2 'data.heatmap_stride=[1,1]' model/encoder=convnext model.decoder.n_blocks=4 'model.decoder.decoder_channels=[-1,384,256,128,64]' model/decoder=smp 'data.img_size=[2048,2048]' 'ema.train_decays=[0.999,0.995]' 'ema.val_decays=[0.999,0.995,0]
```

### (2) Inference to get the OOF predictions
Using trained DSNT models from [(2) Finetune 5-folds Stage 2 DSNT models](#2-finetune-5-folds-stage-2-dsnt-models), to obtain `.pkl` predictions, simply add more command line options:
```bash
task.save_pred=True task.save_pred_dir={YOUR_EXPECTED_PREDICTIONS_SAVING_DIRECTORY} train=False val=True trainer.compile.mode=null ckpt.path={PATH_TO_TRAINED_OUTPUT_DIRECTORY}
```

exact commands were used (2 different commands were used because we had some limited flexibility with Model EMA in our codebase):

